# 模型评测 失败分类与代表性案例

## 性质与边界

本文件记录的是评分器的机械诊断实验，不是真实模型结果，也不是三版本主实验成绩。当前未获得真实模型调用授权，因此没有从最终 60 题的模型表现中挑选“失败案例”。诊断输入在候选输出封存之后构造，只用于证明评分层和归因模板能区分不同边界；它不改变 冻结评测集 冻结题目、参考 SQL、预期结果、容差、停止状态或评分规则。

失败分析采用“最早失守边界 + 全部后续影响”的方式。主分类用于避免把同一根因重复计数；受影响边界与 冻结评测集 原始 `failure_categories` 全部保留，便于审计。业务正确性没有独立金标准的题仍记为 `null`，不会因 SQL 或状态正确而推断为业务正确。

## 分类边界

分类器区分输出契约、检索证据、规划语义、SQL 生成、候选安全选择、安全门、SQL 执行、修复控制、确定性计算、工作流状态、结果语义、lineage、遥测与环境传播。检索质量和 token/费用完整性只能在真实运行记录存在时归因；本轮机械样本不会虚构这两类观测。

## 真实实验时的分析模板

真实运行获授权并完成后，每个失败案例应引用候选封存哈希、运行 ID、case ID、版本、配置、原始输出位置和评分结果；依次陈述最早失守边界、下游影响、证据、可能混杂因素、是否可修复及是否允许重跑。案例选择应覆盖主要失败类别和高风险边界，而不是只挑最戏剧化的错误。若提示词因最终集结果发生调整，后续运行必须标为开发性结果，不能继续称为盲测。
