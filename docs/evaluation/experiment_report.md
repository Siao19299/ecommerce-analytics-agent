# 模型评测 三版本真实模型实验报告

## 结论

在 冻结评测集 冻结的 60 题上，DeepSeek `deepseek-flash`、thinking disabled、temperature 0 的单次正式运行已完成。三个版本读取相同公开题面，候选输出先逐题保存并整批封存，随后才加载私有金标准评分。

检索 + SQL 相对直接 SQL 的结果正确率从 0/51 提高到 16/53，完整逐题契约从 6/60 提高到 22/60。完整 Agent 的结果正确率进一步达到 26/52，但工作流状态和停止原因分别只有 39/60 与 38/60，低于检索版的 50/60 与 50/60。完整 Agent 不是在所有层面都更好。

业务正确性三版分母均为 0：冻结集没有独立业务答案金标准，所以业务答案统一标记为“未独立评估”，不能从 SQL 结果正确率推导业务结论正确率。

## 配对差异与不确定性

三版使用相同题目，因此采用逐题配对差异，并以固定 seed `15015` 对题目做 10,000 次 paired bootstrap。区间仅描述这 60 题样本的敏感性，不包含模型重复采样波动，也不能代表生产流量总体。

- 直接 SQL → 检索 + SQL：完整契约净提升 16/60，差异 +26.7 个百分点，95% bootstrap 区间 `[+16.7, +38.3]`；结果正确在共同可评估的 51 题中净提升 16 题，差异 +31.4 个百分点，区间 `[+19.6, +45.1]`。
- 检索 + SQL → 完整 Agent：完整契约改善 10 题、退化 7 题，净提升 3/60，差异 +5.0 个百分点，区间 `[-8.3, +18.3]`，不足以支持稳定提升结论。
- 检索 + SQL → 完整 Agent：结果正确在共同可评估的 52 题中改善 11 题、退化 1 题，差异 +19.2 个百分点，区间 `[+7.7, +30.8]`。
- 同一对照中，完整 Agent 的状态正确率差异为 -18.3 个百分点，区间 `[-30.0, -6.7]`；stop reason 差异为 -20.0 个百分点，区间 `[-31.7, -10.0]`。

Wilson 区间仍保留在每版聚合结果中；paired bootstrap 用于版本间差异。两类区间都不能消除冻结题集的构造偏差。

## 消融解释

直接 SQL 与检索 + SQL 是本次真实模型的检索上下文消融：模型、题目、输出合同、温度、数据库和评分器相同。它仍混有额外输入 token 和提示布局变化，因此结论应表述为“加入现有检索包后相关指标在本题集上改善”，不能声称检索是唯一因果因素。

检索版与完整 Agent 同时改变规划、状态机、安全门、SQL 执行、确定性计算和停止逻辑，不能把差异分别归因于某一个组件。完整 Agent 的 60 次规划产生 49 次 SQL 生成和 0 次修复；没有任何 repair 模型调用。因此追加 repair-off 真实运行不会观察到修复贡献，本次未浪费预算重复运行。安全门和确定性计算边界继续由离线可控回放验证，不执行被拒绝 SQL，也不让模型替代确定性数值。

## 调用、token 与费用

正式主实验合计 229 次模型调用、783,506 tokens，本地按峰时 cache-miss 单价保守估算 $0.2651。共享硬限额账本还包含首次基础设施无效运行 60 次与一次诊断调用，合计 290 次、843,764 输入 tokens、42,556 输出 tokens、保守估算 $0.3042 / ¥2.04。

首次运行因临时评测快照漏复制新的 `ModelResponse` 遥测字段，60 条均成为 `adapter_exception`。该运行在私有评分前失败，产物独立保留为开发性基础设施失败；未修改提示词、题目或评分规则。修复的是快照代码完整性，正式重跑使用提交 `97173a03793704bbbc65f032ec4fd4067abc9a81`。

用户提供的中途供应商控制台快照为 ¥0.09、115 次请求、193,864 tokens。它是异步刷新且可能包含缓存计价的中间值，不是最终账单；不能与本地最坏单价估算强行对齐。

## 失败分析和结论边界

三版共有 127 条逐题契约失败记录。`model_failures.md` 从封存后记录中选择 18 个代表案例，覆盖规划语义、SQL 生成、安全门、执行、结果语义、状态机与环境传播。最大的主失败边界是结果语义：直接版 43 条、检索版 28 条、完整 Agent 18 条。

当前实验不能支持以下结论：

- 不能证明结果会推广到其他模型、温度、时间或真实业务请求分布。
- 不能证明完整 Agent 全面优于检索版；它提高结果层，但状态层明显退化。
- 不能估计修复机制增益，因为主运行没有触发修复。
- 不能报告业务答案正确率，因为没有独立业务金标准。
- 单次 temperature 0 不是重复实验；提供商不支持本次 transport 的 random seed，后端仍可能变化。
- Docker/Compose 只能证明复现包装边界，不能证明生产部署、安全或扩展性。

原始逐题记录、seal、规范化提交、逐题评分和聚合保存在本地忽略目录；公开的结构化摘要为 `docs/reports/model_comparison.json`。
