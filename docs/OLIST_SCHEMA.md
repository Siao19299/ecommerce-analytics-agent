客户记录 1──1 订单，通过 customer_id 关联
订单 1──N 订单明细，通过 order_id 关联
订单 1──N 支付，通过 order_id 关联
商品 1──N 订单明细，通过 product_id 关联
卖家 1──N 订单明细，通过 seller_id 关联

说明：customer_unique_id 用于识别跨订单的同一真实客户；一个 customer_unique_id 可以对应多条 customer_id 记录。

## 事实表与维度表

| 表 | 类型 | 判断理由 |
|---|---|---|
| 订单 | 事实表 | 一行记录一笔订单事件，包含状态和各阶段时间 |
| 订单明细 | 事实表 | 一行记录一个订单明细，包含商品价格和运费 |
| 支付 | 事实表 | 一行记录一次支付，包含支付金额和分期信息 |
| 客户 | 维度表 | 记录是谁 |
| 商品 | 维度表 | 记录是什么 |
| 卖家 | 维度表 | 记录是谁 |

## 简化分析模型

第一版保留订单、订单明细和支付三个不同粒度的事实表，以及客户、商品和卖家三个维度表。严格来说这是简化事实星座；不将明细与支付强行合并，以避免多对多组合造成指标膨胀。

数据库表名为 `fact_orders`、`fact_order_items`、`fact_payments`、`dim_customers`、`dim_products` 和 `dim_sellers`。
