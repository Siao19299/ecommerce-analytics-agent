## 2. 编码前能力审计

GMV/支付对账。同比使用上年同月连接；环比虽然使用 LAG，但额外检查上一行

它们不能直接冒充 Day 10 通用工具：输入和输出没有统一类型；没有缺失、零基期、

“全数据集边界”等同于“某指标期间完整性”，而要求调用方显式提供完整性。

## 3. 已实现能力

### 同比与环比

- 按精确自然月关系匹配：环比为上一自然月，同比为上年同月。
- 缺失比较期返回明确状态，不使用最近一行，不静默补零。
- 当前期和比较期完整性独立记录；机械结果与标准可比性分开。
- 基期为零时保留绝对变化，相对变化为空并返回 zero_baseline。
- 负基期默认不套用正数规模指标的增长率解释。
- 记录负转非负、非负转负等符号翻转。

### 贡献度

- 默认由全部输入分组推导分母，也支持带完整范围元数据的外部分母。
- 指标、期间、筛选、状态、金额口径或完整性不一致时拒绝外部分母。
- unknown 分组明确保留。
- 使用未提前舍入的结果校验贡献度之和；差额、容差和解释全部落盘。
- 零分母不返回伪造的 0%；负分组和非正分母带明确边界。
- 没有按商品品类拆分支付金额，也没有虚构渠道字段。

### 异常检测

第一版方法为仅使用当前期之前数据的 trailing_median_mad：

    robust_z = 0.6745 * (current - history_median) / MAD

默认阈值 3.5；窗口、最低样本数和阈值全部记录。历史必须为连续、完整的自然月。
样本不足、缺月、不完整历史、不完整当前期、MAD 为零和非法阈值均受控处理。
“检测到异常”只表示偏离规则基线，不生成原因归因。

### 结构、展示和可追溯性

- 指标定义从 data/metadata/metric_dictionary.csv 唯一读取。
- SQL 结果适配器拒绝失败、截断、缺列、非法日期和非法数值。
- 输出包含分析类型、指标 ID 与来源、原始输入、时间、当前/比较值、绝对/相对
  变化、状态、完整性、方法、参数、边界和图表数据。
- Day 10 calculation trace 独立于 Day 9 SQL attempt，通过 parent_run_id 和
  source_sql_attempt 连接，并保存输入 SHA-256。
- 表格、条形图/折线图规范和中文结论均由确定性模板生成，不再次计算数值。

## 6. 保留边界

- 指标字典仍是唯一业务口径来源。
- 真实客户仍使用 customer_unique_id。
- 明细和支付同时出现时仍须分别按 order_id 预聚合。
- 支付金额不支持按商品品类拆分；“销售额”不能静默选择口径。
- Day 9 的安全失败、超时和环境错误不能进入 Day 10。
- SQL 安全、修复成功、确定性计算完成和业务结论正确仍是不同结论。
- 没有引入 LangGraph、FastAPI、Streamlit、向量数据库、新 RAG、复杂机器学习
  异常检测、自动归因、Day 14 完整评测集或真实模型解释调用。
- 没有读取 API Key，没有虚构 Token、费用、延迟、异常准确率或业务正确率。
