# Day 15 模块 3：直接 SQL 版本适配器

## 1. 版本边界

直接 SQL 是一次生成的最低基线。逐题只接收公开 `case_id`、问题文本、六张核心表的
字段/类型/键/粒度摘要，以及统一输出 JSON Schema。它不读取指标字典、维度字典、
检索命中、标准 SQL、预期结果、评分规则或私有备注。

适配器不使用 AnalysisPlan、Day 11 状态机、Day 9 修复或 Day 10 确定性计算。传输层
以后可以在外部统一设置有限重试，但一次成功响应只产生一个 SQL attempt；本适配器
不会因 JSON 或结构错误发送纠错 Prompt。

## 2. 为什么允许非 SQL 动作

输出动作包括 `sql`、`clarify`、`refuse` 和 `unanswerable`。这不是给基线增加完整
Agent 能力，而是避免风险题被迫生成伪造 SQL：歧义应澄清，写操作应拒绝，现有数据
不支持时应明确无法回答。动作与载荷使用互斥合同：SQL 动作不得携带停止消息；其他
动作不得携带 SQL 或参数。

## 3. 输出与计量

每题记录原始响应及 SHA-256、解析动作、SQL、命名参数、固定脱敏失败类型、模型标识、
延迟、输入/输出 token、传输 attempt 和模型调用数。提供商未返回延迟或 token 时保存
`null`，不按文本长度猜测。格式错误仍保存原始响应，但不会自动修复。

本模块止于候选生成和结构解析。SQL 安全门、只读 SQLite 执行、状态映射、逐题封存及
私有评分由后续统一运行器负责，防止三个版本各自复制一套执行与评分逻辑。

## 4. 当前证据

当前测试全部使用 `FakeModelClient`，外部 API 调用为 0，真实模型运行为 0。测试验证
一次调用、Schema-only Prompt、四类动作、严格结构、原始失败保留、异常脱敏和未知用量
不猜测。这里没有产生模型准确率或业务正确率。
