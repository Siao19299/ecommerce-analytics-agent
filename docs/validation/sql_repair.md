# SQL 修复：SQL 错误修复与可观测性验收

## 1. 起点复核

开始时实际确认：分支为 `main`，工作区干净，HEAD 为
`8cf1d52 docs: record SQL 修复 handoff`，SQL 安全 功能提交为
`f753e88 feat: complete SQL 安全 SQL safety controls`。项目使用独立 `.venv`、
Python 3.11.9、SQLGlot 30.18.0，依赖约束为 `sqlglot>=30.0,<31.0`。

开始前全量实跑为 155 passed。数据库实际为六张核心表、38 个字段；
`data/raw/` 中 `archive.zip` 和九个 CSV 的大小及 SHA-256 全部匹配清单。SQL 安全
结果文件记录的 16/16 安全案例、12 个安全拒绝进入 SQLite 数为 0，以及数据库
前后哈希一致均得到交叉核对。

## 2. 可达错误审计

SQL 安全 已在 SQLite 前拦截解析失败、多语句、未知表、未知/歧义字段、计划外对象、
参数合同错误和 Schema 漂移。因此这些错误不是 SQL 修复 的数据库后置修复样本，
故障案例保留原有安全门约束。

真实数据库验证了可穿过安全门的 SQLite 执行错误，包括：不存在的标量函数、
函数参数数量错误、复合 SELECT 列数不一致、CTE 声明列数不一致、非法 ESCAPE
宽度和窗口函数参数错误。只有命中窄白名单、实际进入 SQLite 且可在原计划范围
内局部修改的错误具备修复资格。数据相关或陌生错误默认拒绝修复。

| 类别 | 是否修复 | 处理 |
|---|---:|---|
| SQL 安全 安全失败、Schema 漂移、参数合同错误 | 否 | 直接返回 |
| 查询超时或资源失败 | 否 | 返回资源失败，不让模型试探 |
| 白名单内的 SQLite SQL 结构错误 | 是 | 有限修复并完整复验 |
| 数据库不存在、损坏、锁定、权限或未知环境错误 | 否 | 返回环境/未知数据库错误 |
| SQL 可执行但指标口径错误 | 否 | 留给独立业务结果评测 |
| 模型 429、网络超时或 5xx | 不占 SQL 修复次数 | 模型客户端有限指数退避 |

## 3. 有限修复与循环保护

`max_repair_attempts` 是生成修复候选的硬上限；最大 SQL 候选数为首次 SQL 加
最大修复次数。模型传输 attempt 独立计数，同一修复调用的 429/超时重试不会
增加 SQL attempt。

修复上下文只包含已验证 AnalysisPlan、规范指标/维度/字段范围、原 SQL、脱敏
SQLite 错误、固定参数合同和已尝试哈希。修复模型不能增加表字段、改变指标口径、
扩大 JOIN 范围或绕过命名参数。每条候选重新经过 SQL 安全 的 AST、全局/计划两级
允许列表、参数合同、Schema 检查和资源限制。

SQLGlot 按 SQLite 方言生成稳定规范化 SQL，再计算 SHA-256。同一个 `run_id`
内若模型原样返回或回到任何历史候选，候选计入 SQL attempt，但不进入 SQLite，
并以 `duplicate_candidate` 停止。

## 4. 可观测性

同一次请求始终使用同一个 `run_id`。逐 attempt trace 保存：

- SQL/repair attempt 编号、来源 attempt 和触发规则；
- 候选 SQL、规范化值、SHA-256 和参数；
- 数据库错误类别及脱敏消息、修复上下文来源；
- 完整安全 trace、是否进入 SQLite、执行耗时和结果；
- 模型名、传输次数、Token、延迟和 finish reason；
- 最终状态与停止原因。

假模型没有真实 Token 或延迟时保存 `null`，不写成零。本地绝对路径从错误文本中
移除。没有读取、打印或保存 API Key。安全通过、修复成功和业务结果正确分别
记录；本批次没有独立业务参考结果，因此全部为 `not_evaluated`。

## 5. 离线批次结果

九个案例使用明确标记的假模型响应和真实本地 SQLite：

| 统计 | 数量 |
|---|---:|
| 总请求 | 9 |
| 首轮成功 | 1 |
| 合格且实际进入修复 | 5 |
| 修复成功 | 2 |
| 达到修复上限 | 1 |
| 重复候选停止 | 1 |
| 安全拒绝（初始或修复候选） | 2 |
| 环境错误 | 1 |
| 资源失败 | 1 |

核心自动修复成功率为：

```text
修复成功数 / 实际进入修复的合格案例数 = 2 / 5 = 40%
```

分母不包含首轮成功、安全拒绝、环境错误或超时。九例 9/9 符合预设停止条件；
其中一例用假客户端模拟同一修复轮内两次暂时性传输失败，第三次返回候选，trace
正确记录 3 次传输尝试但只计 1 次修复。外部 API 调用为 0，成本未计算。

完整逐题 trace 位于 `docs/reports/sql_repair.json`，可再生成副本位于
`data/processed/repair/offline_benchmark.json`。案例来源为
助手根据需求构造的合成故障集，原始来源标签保留在结构化结果中。
