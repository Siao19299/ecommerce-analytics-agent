# Olist 表结构审计

审计日期：2026-09-05
数据版本：`data/metadata/olist_file_manifest.csv` 中记录的原始 CSV
审计方式：使用项目 `.venv` 读取实际 CSV，检查空键、重复键、外键缺失和关系数量。

## 计数口径

- `重复行数`：非空键总数减去不同非空键数量，不等于“存在重复的键数量”。
- `孤儿行数`：子表外键非空，但在父表主键集合中不存在的行数。
- 候选主键结论只描述当前 Olist 数据快照；数据库约束还需结合字段语义决定。

## 建模影响

- 订单、明细和支付不能在订单级预聚合前直接同时连接，否则同一订单内会形成明细数 × 支付数的组合。
- `customer_id` 在当前原始订单表中是一对一连接；分析复购时应通过客户表取得 `customer_unique_id`。
- 地理位置邮编前缀不唯一，不能直接作为唯一维度表主键，也不应直接连接到订单明细。
- 商品品类翻译和邮编地理关联存在缺失或未匹配记录，第一版不建立严格外键约束。
- 后续建表脚本可对已验证的核心键添加约束；地理位置表应保留为原始观测表或先生成聚合维表。
