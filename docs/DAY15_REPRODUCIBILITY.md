# Day 15 模块 2：评测隔离、运行清单与可重复性元数据

## 1. 隔离模型

候选适配器的逐题输入固定为 `PublicCase(case_id, question)`。公开清单必须匹配冻结
SHA-256，恰好包含 60 个唯一 case_id，且每行只能通过严格模型解析出这两个字段。
运行配置不保存数据集私有路径、标准 SQL、预期结果、比较规则或私有备注。

这是受控评测代码的能力隔离，不是针对恶意本地 Python 代码的操作系统安全沙箱。
真实模型只能收到从 PublicCase 和该版本已登记公共上下文构造的消息。候选适配器后续
应以依赖注入接收这些对象，不得自行接受仓库根目录或 reference 路径。

## 2. 封存后评分

候选 JSONL 完整落盘后计算 SHA-256、字节数和非空行数，产生
`SealedCandidateArtifact`。只有恰好 60 行且文件哈希未在封存后改变，才能取得
`ScoringAuthorization`；私有数据集和 references 路径只在该授权之后返回给评分器。
这将“先保存全部候选，再加载金标准”从约定变成程序前置条件。

封存证明本身不判断每行候选合同是否正确；候选合同解析属于统一运行器阶段。格式错误
仍应原样封存，并在评分时归为输出合同失败，不能在封存前用金标准指导修补。

## 3. 运行清单

每次运行记录：

- 版本、运行目的和 fake/replay/real provenance；
- 冻结数据集版本、内容哈希、文件哈希、公开清单哈希和数据库哈希；
- Git commit、工作区是否干净、Python、平台及是否使用项目 `.venv`；
- provider、model ID、temperature、top-p、seed、最大输出 token、单次超时；
- Prompt、检索配置和适配器配置的规范 SHA-256；
- 重复实验序号、是否获得外部 API 授权；
- 候选是否收到私有资产、候选阶段是否加载私有参考、API Key 值读取次数。

清单永远不读取或保存 API Key 值。真实模型 provenance 必须同时满足显式授权和非
offline provider；fake/replay 运行不得携带 API 授权。检索配置哈希只允许出现在
`retrieval_sql` 与 `full_agent`，从而防止版本边界漂移。

## 4. 当前状态

本模块没有调用模型、执行候选 SQL 或加载私有评分结果。新增代码仅校验公开输入、捕获
非敏感运行环境、原子写入清单、封存候选文件并控制私有评分入口。真实模型运行仍为 0，
外部 API 调用仍为 0。
